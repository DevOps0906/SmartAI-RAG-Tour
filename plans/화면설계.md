- 문서 버전: v1.0 / 작성일: 2026-10-16
- 관련 문서: 기획서(`plans/기획서.md`), 개발서(`develop/개발서.md` 5장 State, 17장 웹 계층), `Designs/DASHBOARD_PATTERNS.md`(구조 A~O), `Designs/DASHBOARD_VISUAL.md`(시각 V-A~V-N)

## 1. 7단계 분석 (DASHBOARD_VISUAL 1장)

화면을 설계하기 전에 거친 분석이다. 각 단계의 결과가 2장 화면 표와 7장 작업 지시의 근거다.

| 단계 | 판단 | 결과 |
|---|---|---|
| 1. 왜 들어오나 | 여행을 계획하려고, 만들던 계획을 이어서 하려고 | "만드는 도구"형. 홈 = 여행 작업실 + 사이드바의 최근 대화 + "새 여행 계획" 주 행동 |
| 2. 구조 | 대화로 계획을 만들고, 결과(날씨·환율·추천·일정)를 옆에 모아 본다 | **A(앱 셸) + 고유(여행 보드) + AI 패널(플로팅 위젯 변형)**. 그래프 실행 과정은 **N(실행 모니터) 축소형** |
| 3. 트레이딩 적합도 | 실시간 숫자를 보고 즉시 행동하지 않는다(환율은 참고값) | **부적합**: 캔들, 호가창, 네온 다크 금지 |
| 4. 선택 기준 | 빈도: 여행 계획 때 몇 번 / 레코드: 도시 5개(10개 이하) / 사용자: 일반 여행자 | 카드형, **라이트 기본** + 큰 CTA, 기본 밀도 |
| 5. 시각 | 주 콘텐츠(보드) + 오른쪽 아래 플로팅 챗봇 위젯, 출처 표시 필수 | **V-L(#53) AI 코파일럿 패널**. 결과 카드는 V-F(#17, #25) 단일 위젯 |
| 6. 빼는 것 | | KPI 카드 나열, 게이지·도넛, 차트 라이브러리, 글로우·그라디언트(셸), 목업 연출 |
| 7. 색·숫자 | | 포인트컬러 1개(딥 오션 블루 계열, 보라 사용 안 함), 환율·기온은 tabular 숫자에 오른쪽 정렬, 증감은 부호와 텍스트를 함께 표시 |

**두 겹 표기**

```
A + 고유(여행 보드) + AI 패널(플로팅 위젯 변형) · 시각 V-L(#53), 결과 카드 V-F(#17, #25)
적합도: 부적합 / 기본 테마: 라이트(다크 지원)
```

### 2.1 S0 랜딩과 공통 GNB (FR-13)

- **라우트**: `/` 랜딩, `/planner` 작업실(`?thread_id=`, `?debug=1` 유지). 예전 `/?thread_id=` 는 `/planner` 로 리다이렉트. 모달 "계획 만들기"는 랜딩에서도 `/planner?thread_id=…` 로 이동해 자동 생성이 시작된다.
- **GNB(`partials/gnb.html`, 두 페이지 공용)**: 로고(아이콘 + "스마트 여행 비서", `/`), 검색창("떠나고 싶은 여행지를 검색하세요", Enter, 미지원이면 아래에 "아직 준비 중인 여행지예요. 선택 가능: …"), 여행지 드롭다운(5개 도시, 누르면 그 도시가 선택된 계획 모달), 인기 코스(`/#popular`), 여행 작업실(`/planner`), 테마 전환, 주 행동 "새 여행 계획". 1024px 미만은 햄버거 → 전체메뉴 패널. `/planner` 의 대화 목록 토글은 GNB 아래 얇은 바에 둔다.
- **랜딩 구성**: 히어로 슬라이더(5개 도시 일러스트, 두 줄 헤드라인, 한 줄 설명, 해시태그 3개, "이 여행지로 계획하기"/"인기 코스 보기", 이전·다음 원형 버튼, 점 인디케이터, 일시정지 버튼, 6초 자동 넘김, 호버·포커스 시 멈춤, reduced-motion 이면 자동 넘김 없음, 좌우 키) → 내 여행 계획(로컬 저장본이 있을 때만) → 인기 코스 10장(국가 라벨, "[도쿄] 미식·야경 3일", 해시태그, "1인 예상 경비 약 OO만원~ 참고용·항공 제외", 375px 2열) → 여행지 둘러보기 → 이렇게 계획해요 → 푸터("가이드 정보는 2026년 기준 참고용").
- **색**: 도시별 토큰 `--color-dest-{city}[-soft|-sky|-mid|-pop]`(라이트·다크 두 벌). 템플릿에 hex·그라디언트·그림자 없음. 포인트 컬러는 기존 accent 1색.
- **로컬 저장(내 여행 계획)**: 계획 생성·상세 요청 스트림이 끝날 때마다 서버의 `GET /plan/{thread_id}.json` 을 `localStorage["smart-travel:plans"]` 에 저장(최신순 최대 20, 같은 thread_id 덮어쓰기, 오류는 무시). 랜딩 "내 여행 계획" 카드(요약, 장소 칩 일부, 저장 시각)는 `/planner?thread_id=` 로 간다. 서버에 대화가 없으면 `/planner` 가 저장본으로 읽기 전용 보드를 그리고 "저장된 계획(오프라인 사본)" 배지를 단다. 각 카드와 여행 요약 바의 "이 기기에서 삭제"는 `<dialog>` 확인 후 로컬 항목만 지운다.

### 3.1 데스크톱 (1280px 기준)

```
┌──────┬────────────────────────────────────────────────────┐
│ 사이드 │ 페이지 헤더: 도쿄 · 일본 · JPY            [새 여행 계획] │
│ 바    ├────────────────────────────────────────────────────┤
│ ─ 새  │ [날씨 카드]  [환율 카드]                              │
│ ─ 최근 │ [추천·가이드 요약 카드 (출처: tokyo.txt#음식)]          │
│  대화  │ [일정 카드 (3박4일)]            ┌──────────────────┐  │
│       │                              │ AI 여행 비서   ＋ ✕│  │
│       │                              │  봇 말풍선 / 출처칩 │  │
│       │                              │       사용자 말풍선 │  │

└──────┴────────────────────────────────────────────────────┘

```

| 영역 | 폭 | 내용 |
|---|---|---|
| 내 여행 기록 패널 | 256px(xl 288px), 항상 보임 | `새 여행 계획` 버튼, 계획했던 여행 목록(`GET /threads`). 항목: 여행 요약("파리 10/16~10/19 · 3박4일"), 장소 칩 2~3개, 만든 시각, 현재 보는 항목 `aria-current`. 일반 대화는 아래 "대화" 그룹. 30개씩 "더 보기". 이 기기(PlanStore)에만 있는 계획은 "이 기기에 저장된 사본" 표시로 같은 목록에 합치고 thread_id 로 중복 제거. 항목마다 "기록에서 삭제"(dialog 확인, `DELETE /threads/{id}` + 로컬 사본 삭제). 항목을 누르면 페이지 이동 없이 보드·요약 바·챗봇 대화가 그 기록으로 교체(`hx-push-url`, 뒤로가기는 popstate 로 다시 불러옴) |
| 페이지 헤더 | 가운데 열 상단 | 목적지 · 국가 · 통화(`entities.destination_ko`, `entities.currency`). 값이 없으면 `새 여행 계획`. 주 행동 버튼 1개(`새 여행 계획`) |
| 여행 보드 | 가운데 열 | **여행지 선택 섹션(맨 위)**, 날씨·환율 카드 2열, 그 아래 추천·가이드 카드, 일정 카드 순(4장). 위계는 "목적지 → 결과 카드 → 근거(출처)" |
| AI 챗봇 위젯 | 오른쪽 아래 플로팅. FAB 56px, 대화창 폭 24rem · 높이 `min(40rem, 100dvh - 7rem)` | 5장 |

- 셸 바깥 배경은 `--color-bg`, 카드는 `--color-surface` + `--color-border` 테두리(그림자 대신 테두리).
- 현재 위치 표시, `Ctrl+K`로 입력창 포커스(검색 대신 질문 입력으로 대체)를 지원한다.

### 3.3 375px 동작

- 페이지 전체 가로 스크롤 없음.
- 날씨·환율 카드는 1열로 쌓는다. 카드 안 표·긴 출처 파일명은 줄바꿈하거나 카드 안에서만 가로 스크롤한다.
- 터치 대상은 최소 44px. 예시 질문 버튼은 한 줄에 하나씩 쌓는다.
- 실행 흐름(S2)은 노드 이름·상태 배지·소요 ms를 두 줄 구성으로 줄인다(이름+배지 / 설명+ms).

## 4. 보드 카드 명세

모든 카드는 State 필드만 읽는다(개발서 5장 `TravelState`). 웹 계층은 SSE `board` 이벤트에서 해당 필드를 부분 템플릿(`partials/`)으로 렌더링한다.

### 4.1 카드가 읽는 State 필드 요약

| 카드 | 읽는 State 필드 | 채우는 노드 |
|---|---|---|
| 날씨 | `weather`(8.1 스키마), `entities.destination_ko`, `entities.travel_date` | `weather_tool` |
| 환율 | `exchange`(8.2 스키마), `entities.currency`, `entities.amount` | `exchange_tool` |
| 추천·가이드 | `rag_docs`(`content`, `city`, `section`, `source`, `score`), `entities.interests`, `intent` | `rag_search` |
| 일정 | `rag_docs` 중 `section`이 "일정 예시"인 항목, `entities.days`, `entities.destination_ko` | `rag_search` |
| 페이지 헤더 | `entities.destination_ko`, `entities.currency` | `analyze_input` |
| 오류·폴백 표시 공통 | `errors`, `weather.source`, `weather.fallback_reason`, `exchange.source`, `exchange.fallback_reason` | 각 노드 |

### 4.2 날씨 카드

| 항목 | 표시 |
|---|---|
| 제목 | `날씨` + 도시명(`weather.city_ko`) |
| 큰 숫자 | `weather.temp_c` (예: `24°`), tabular 숫자, 보드에서 가장 큰 글자 1개 |
| 보조 | 체감 `weather.feels_like_c`, 습도 `weather.humidity`%, 상태 `weather.condition`(텍스트) |
| 한 줄 조언 | `weather.advice` |
| 기준 | `weather.date` 기준일. 출처 배지: `weather.source`가 `live`면 `실시간`, `mock`이면 `예시 데이터` |

| 상태 | 표시 |
|---|---|
| 기본 | 위 항목 전부. 숫자는 오른쪽 정렬 |
| 로딩 스켈레톤 | `weather_tool` 노드 `node_start` ~ `node_end` 사이. 큰 숫자 자리와 줄 3개를 스켈레톤으로 표시 |
| 빈 상태 | `weather`가 `None`: "도시를 알려 주시면 날씨를 보여드려요." + 예시 질문 버튼 `도쿄 날씨 알려줘` |
| 오류 + 폴백 배지 | `source=mock`: 값은 그대로 보이고 `예시 데이터` 배지 + 툴팁에 `fallback_reason`. `ok=False`: 값 대신 "날씨를 가져오지 못했어요. 도시를 확인하고 다시 시도해 주세요." + `다시 시도` 버튼 |
| 권한 없음 | 해당 없음(로그인·권한 없음) |

### 4.3 환율 카드

| 항목 | 표시 |
|---|---|
| 제목 | `환율` + 통화 코드(`exchange.target`) |
| 큰 숫자 | 환산 결과 `exchange.converted` + 통화 단위 (예: `54,945 JPY`), 천 단위 구분, tabular 숫자 |
| 보조 | 입력 금액 `exchange.amount` `exchange.base`, 적용 환율 `1 JPY = 9.1 KRW` 형식(`exchange.rate`). 증감 표시는 쓰지 않는다(참고값) |
| 기준 | 기준일 `exchange.rate_date`(live만). 출처 배지: `live`면 `실시간`, `mock`이면 `고정 환율`. 문구 "실제 수수료 별도" |

| 상태 | 표시 |
|---|---|
| 기본 | 위 항목 전부 |
| 로딩 스켈레톤 | `exchange_tool` 실행 중. 큰 숫자 자리와 줄 2개 |
| 빈 상태 | `exchange`가 `None`: "금액과 나라를 알려 주시면 환산해 드려요." + 예시 질문 버튼 `50만원이면 엔화로 얼마야?` |
| 오류 + 폴백 배지 | `source=mock`: `고정 환율` 배지 + `fallback_reason` 툴팁. `ok=False`: `exchange.error` 문구를 사람 말로 바꿔 표시("금액은 0보다 커야 해요.") + `다시 입력` 버튼 |
| 권한 없음 | 해당 없음 |

### 4.0 새 여행 계획 모달 (FR-09 → FR-10)

보드 상단의 "여행지 선택" 섹션은 없앴다. 지원 여행지 카드는 모달 1구획으로 옮겼다. 미지원 안내 말풍선의 컴팩트 선택 카드(`data-ask`)는 그대로다.

| 항목 | 내용 |
|---|---|
| 열기 | 헤더 "새 여행 계획"(모바일 "새 계획"), 빈 보드 CTA "새 여행 계획으로 시작해 보세요", 계획 요약 바의 "계획 수정"(값이 채워진 채로 열림) |
| 구조 | `<dialog id="plan-modal" aria-labelledby>`, `showModal()` 로 포커스 가둠(+Tab 순환), Esc/배경 클릭/닫기 버튼으로 닫음, 640px 미만 전체 화면 |
| 1 여행지 | 라디오 카드 5개(`supported_destinations()`). 선택은 테두리·배경 + 체크 + "선택됨" 글자. 고르면 `GET /places?city=` 로 3구획 칩을 불러옴 |
| 2 여행 일정 | 출발일 date(기본 오늘, min=오늘) + 여행 일수 세그먼트 라디오 그룹 "1일차 … 5일차"(`role="radio"` `aria-checked`, 좌우 방향키 이동, 기본 3일차). 도착일 입력 없음. 선택 즉시 "10/16(금) ~ 10/18(일) · 2박 3일" 표시 |
| 3 원하는 장소 | 가이드 "주요 명소" 체크박스 칩(다중) + 직접 입력(쉼표 구분), 최대 10곳. 비우면 "AI가 가이드를 바탕으로 추천해요" |
| 제출 | "계획 만들기" → `POST /plan`. 오류는 400 으로 `#plan-errors` 에 표시. 성공하면 랜딩에서는 `HX-Redirect: /planner?thread_id=…`(일반 요청은 303). 작업실에서는 페이지를 새로 고치지 않고 응답(`HX-Push-Url`, `HX-Retarget: #board-root`)으로 보드·요약 바·챗봇 대화를 새 thread 로 교체하고 모달을 닫는다(입력·취소 중에는 현재 화면이 그대로, 실패하면 모달 안에 오류). 새 화면은 챗봇 위젯에 요약 문장("도쿄 10/20~10/23 3박4일, 아사쿠사·시부야 포함 계획 만들어줘")을 사용자 메시지로 보이고 스트림을 자동 시작 |

### 4.0.1 계획 보드 배치 (trip 이 있을 때)

맨 위 여행 요약 바(도시 · 국가, 날짜 · N박M일, 장소 칩, "AI 추천" 배지, "계획 수정") 바로 아래에 "요청한 정보"(전체 폭) → "환율" / "가이드"(2열) → "일정"(가장 넓게, 일차 · 날짜 · 항목 · 날씨 메모) / "여행기간중 날씨현황"(N개 행: 일차·날짜, 최저/최고, 상태, 강수확률, 예보·예상 기후·예시 배지) 순서(2026-10-16 사용자 요청으로 재배치). 계획이 없으면 CTA + 기존 빈 카드. 일정 카드의 각 일차 아래에 요청한 정보가 있으면 "요청한 정보 보기" 앵커 링크.

### 4.0.2 debug

답변 아래 "실행 흐름 보기"(노드·상태·ms)와 "총 N ms"는 `?debug=1` 일 때만 그린다. 쿼리는 사이드바 링크, 채팅 접수(`debug` 필드), SSE(`/chat/stream?debug=1`), 모달 제출에 유지된다.

### 4.6 카드 공통 규칙

- 한 카드에서 큰 숫자는 1개만 쓴다. 게이지·도넛·차트는 쓰지 않는다.
- 폴백 배지는 색만으로 구분하지 않는다. 아이콘 + 텍스트(`예시 데이터`, `고정 환율`)를 함께 쓰고 `--color-warning` 계열 토큰을 사용한다.
- 숫자는 모두 tabular, 오른쪽 정렬. 증감을 표시할 일이 생기면 `--color-up`, `--color-down`과 부호(+/−)·화살표·텍스트를 함께 쓴다.
- 새 데이터가 도착하면 카드 배경을 1회만 짧게 강조(`--color-accent-soft`)한다. 반복 깜빡임은 금지. 구현: 새 데이터 카드 래퍼에 `board-fresh` 클래스(`app.src.css`의 `board-flash` 1.2초 1회), `prefers-reduced-motion`이면 생략. 오류 카드는 `card` 매크로의 `action` 슬롯에 `다시 시도`(마지막 질문 재전송) 또는 `다시 입력`(입력창 포커스) 버튼을 둔다.

## 5. AI 챗봇 위젯

### 5.1 구성

| 영역 | 내용 |
|---|---|
| 열기·닫기 | 오른쪽 아래 FAB(56px 원형, `aria-label` "AI 여행 비서 열기", `aria-expanded`). 열리면 ✕. `Ctrl+K` 열기+포커스, `Esc` 닫기(포커스는 FAB로). 상태는 localStorage 에 저장, 기본값은 빈 대화의 첫 방문 + 데스크톱이면 열림 |
| 헤더 | 봇 아바타, "AI 여행 비서", 상태(대기 중 / 답변 작성 중…), 닫기(✕, Esc는 위젯만 숨기고 SSE 스트림·보드 갱신은 계속됨. 페이지 이동 링크 없음) |
| 메시지 스레드 | 메신저형. 사용자 말풍선(오른쪽, `--color-accent` 배경 + `--color-accent-fg` 글자), 봇 말풍선(왼쪽 아바타 + `--color-surface-muted` 배경). 각 메시지 아래 작은 시간. 대기 중에는 타이핑 점 3개(reduced-motion 이면 "답변 작성 중…" 텍스트). 읽으려고 위로 스크롤했으면 자동 스크롤하지 않음 |
| 출처 칩 | 비서 메시지 아래에 `{도시 한글명} 가이드 · {섹션}` 칩(예: `파리 가이드 · 주요 명소`, 파일명·title 속성 없음), 날씨·환율 출처 칩(`실시간`/`예시 데이터`/`고정 환율`). 칩을 누르면 해당 보드 카드로 스크롤하고 하이라이트 |
| 실행 흐름(S2) | 비서 말풍선마다 `▸ 실행 흐름 보기` 접이식. 기본은 접힘 |
| 입력창 | 여러 줄 입력(`Enter` 전송, `Shift+Enter` 줄바꿈), 전송 버튼은 동사 `보내기`. 응답 중에는 입력창은 유지하고 전송 버튼만 비활성 |
| 미지원 여행지 | 5개 외 나라·도시를 말하면 "지금 요청하신 {이름}의 정보는 아직 존재하지 않습니다. 아래 여행지 중에서 선택해 주세요." + 말풍선 안에 컴팩트 선택 카드(보드와 같은 매크로). 누르면 해당 도시 질문을 전송. 보드는 바뀌지 않는다. 새로고침 복원 시에도 같은 말풍선 아래 카드 표시. 지원 도시와 함께 말하면 정상 답변 끝에 안내 한 줄 |
| 빈 대화 | 봇 인사("안녕하세요! 여행지, 날씨, 환율, 일정을 물어보세요.") + 예시 질문 칩 4개. 누르면 입력창에 채움 |

### 5.2 실행 흐름 (S2)

N(작업·실행 모니터)의 축소형이다. 그래프 한 번 실행을 노드 단위 목록으로 보여 준다. SSE `node_start`/`node_end` 이벤트로 갱신한다(개발서 17장).

| 노드명 | 화면 표시 이름(보조 설명) | 쓰는 State 필드 |
|---|---|---|
| `analyze_input` | 질문 분석(의도·목적지 파악) | `intent`, `entities`, `pending_intents` |
| `rag_search` | 가이드 검색 | `rag_docs` |
| `weather_tool` | 날씨 조회 | `weather` |
| `exchange_tool` | 환율 계산 | `exchange` |
| `clarify` | 되묻기 | `clarify_question` |
| `generate_answer` | 답변 작성 | `final_answer` |

| 상태 | 표시 (아이콘 + 텍스트 + 배지) | 비고 |
|---|---|---|
| 대기 | 빈 원 + `대기` | 아직 실행 안 됨. 해당 의도가 큐(`pending_intents`)에 있을 때만 행을 미리 그린다 |
| 실행 | 회전 아이콘 + `실행 중` | `node_start` 수신. 소요 시간은 숫자 대신 경과 표시 |
| 성공 | 체크 + `성공` + `412 ms` | `node_end` 수신. 소요 ms는 오른쪽 정렬, tabular 숫자 |
| 실패 | 경고 + `실패` + 한 줄 사유 | 사유는 사람 말로 한 줄. 펼치면 `errors` 원문 |
| 폴백 | 되돌림 화살표 + `폴백` + `예시 데이터` 또는 `고정 환율` | `source=mock`일 때. 단계는 성공으로 끝났으나 대체 데이터를 썼다는 뜻 |

규칙:
- 실행하지 않은 노드(예: 날씨만 묻는 질문의 `exchange_tool`)는 목록에 표시하지 않는다. 경로는 실제 실행 순서 그대로 표시한다.
- 복합 의도는 `analyze_input` -> `rag_search` -> `weather_tool` -> `exchange_tool` -> `generate_answer` 순서로 쌓인다.
- 진행률이 없는 무한 스피너는 쓰지 않는다. 노드별 상태 아이콘으로 현재 위치를 보인다.
- 합계 소요 시간을 목록 맨 아래에 한 줄로 표시한다(`합계 2,310 ms`).
- 이 영역은 과제의 State/Node/Edge 시연용이므로 `route_by_intent` 선택 결과(다음 노드)를 각 행의 보조 설명에 `다음: weather_tool` 형식으로 함께 적는다.

### 5.3 예시 질문 4개

| 번호 | 문구 | 시연하는 경로 |
|---|---|---|
| 1 | 5월에 3박 4일로 맛집 위주로 갈 만한 해외 도시 추천해줘 | analyze_input -> rag_search -> generate_answer |
| 2 | 다음 주 파리 날씨 어때? | analyze_input -> weather_tool -> generate_answer |
| 3 | 도쿄 가는데 50만원이면 엔화로 얼마야? | analyze_input -> exchange_tool -> generate_answer |
| 4 | 7월에 뉴욕 5일 여행 가려는데 날씨랑 환전, 일정도 알려줘 | analyze_input -> rag_search -> weather_tool -> exchange_tool -> generate_answer |

- 되묻기(`clarify`) 경로는 예시 질문에 넣지 않는다. 사용자가 "환율 알려줘"처럼 정보가 부족하게 입력하면 자연스럽게 시연된다.

| 보드 전체 빈 상태 | 여행 질문을 보내면 날씨·환율·추천·일정이 여기에 모여요. | 보드 |
| 날씨 빈 상태 | 도시를 알려 주시면 날씨를 보여드려요. | 날씨 카드 |
| 환율 빈 상태 | 금액과 나라를 알려 주시면 환산해 드려요. | 환율 카드 |
| 추천 빈 상태 | 아직 추천할 여행지가 없어요. 취향이나 계절을 알려 주세요. | 추천·가이드 카드 |
| 일정 빈 상태 | 일정을 만들려면 목적지와 기간을 알려 주세요. | 일정 카드 |
| 폴백 배지(날씨) | 예시 데이터 | 날씨 카드 |
| 폴백 배지(환율) | 고정 환율 | 환율 카드 |
| 폴백 안내(툴팁) | 실시간 조회에 실패해 예시 데이터로 보여드려요. | 배지 툴팁 |
| 날씨 오류 | 날씨를 가져오지 못했어요. 도시를 확인하고 다시 시도해 주세요. | 날씨 카드 |
| 환율 오류(금액) | 금액은 0보다 커야 해요. 금액을 다시 입력해 주세요. | 환율 카드 |
| 미지원 도시 | 현재 가이드에는 도쿄·파리·방콕·뉴욕·제주만 있어요. 비슷한 분위기의 파리는 어떠세요? | AI 패널 / 추천 카드 |
| 되묻기 | 어느 나라(통화)와 금액이 궁금하신가요? 예: "도쿄에서 쓸 50만원". | AI 패널 |
| 서버 오류 | 응답을 만들지 못했어요. 잠시 후 다시 시도해 주세요. | AI 패널 |
| 연결 끊김 | 연결이 끊겼어요. 다시 시도해 주세요. | AI 패널 |
| 실행 흐름 실패 | 날씨 조회에 실패했어요. 다른 정보는 그대로 사용했어요. | 실행 흐름 행 |
| 입력창 안내 | 여행에 대해 무엇이든 물어보세요 | 입력창 placeholder |

### 6.3 금지

- "에러가 발생했습니다" 같은 원인 없는 문구, 영문 예외 이름, "Oops" 같은 가벼운 표현.
- 한 화면에서 같은 행동을 다른 동사로 부르기(`전송`/`보내기` 혼용 금지).
- 색만으로 상태 표시.

## 7. 작업 지시와 검증

### 7.1 작업 지시 블록 (DASHBOARD_VISUAL 10장 형식)

**S1 여행 작업실**
```
패턴: A + 고유(여행 보드) + AI 패널(플로팅 위젯 변형)
시각: V-L(#53), 결과 카드 V-F(#17, #25) / 적합도: 부적합 / 기본 테마: 라이트(다크 지원)
빼거나 바꿀 것: V-L의 분석 리포트·차트, KPI 카드 나열, 게이지·도넛, 셸·사이드바의 글로우·그라디언트,
               목업·퍼스펙티브 연출, 상승·하락 색(환율은 참고값이라 증감 표시 안 함),
               권한 없음 상태(해당 없음), 설정·로그인(범위 밖)
```

**S2 실행 흐름**
```
패턴: N 축소형 (S1의 챗봇 위젯 안 접이식 영역)
시각: 시각 없음 / 적합도: 부적합 / 기본 테마: 라이트(다크 지원)
빼거나 바꿀 것: N의 실행 목록·재시도·취소, 진행률 바, 무한 스피너(노드별 상태 아이콘으로 대체)
```

**S3 컴포넌트 미리보기**
```
패턴: 고유
시각: 시각 없음 / 적합도: 부적합 / 기본 테마: 라이트·다크 나란히
빼거나 바꿀 것: 운영 화면 링크 노출(개발용), 장식 요소
```

### 7.2 검증 체크리스트 (스크린샷으로 확인)

1280px과 375px, 라이트와 다크를 모두 확인한다.

- [ ] 1장 7단계 결과가 2장 화면 표와 7.1 작업 지시에 적혀 있다
- [ ] 위계가 "목적지 -> 결과 카드 -> 근거(출처)" 순서다
- [ ] 포인트컬러가 화면에 1개(딥 오션 블루 계열)이고 보라가 없다
- [ ] 환율·기온 등 숫자가 tabular, 오른쪽 정렬이다. 증감을 쓰는 곳은 부호·텍스트를 함께 표시한다
- [ ] 글로우·그라디언트가 셸·사이드바·카드에 없다
- [ ] 게이지·도넛·차트·KPI 카드 나열이 없다
- [ ] 목업·퍼스펙티브·실사 배경 같은 연출이 없다
- [ ] 카드마다 상태 5종(기본/스켈레톤/빈 상태/오류+폴백 배지/권한 없음=해당 없음)이 구현되어 있다
- [ ] 추천·가이드 카드와 답변에 출처 칩이 있고, 폴백 값에는 배지가 있다
- [ ] 실행 흐름에 노드 상태 5종(대기·실행·성공·실패·폴백)과 소요 ms가 보인다
- [ ] 375px에서 페이지 가로 스크롤이 없고 사이드바는 햄버거, 대화는 FAB로 여는 전체 화면 시트다
- [ ] 키보드로 전송·사이드바·실행 흐름 펼침이 가능하고 포커스 링(`--color-focus`)이 보인다
- [ ] 템플릿에 hex 직접 사용이 0건이다 (`grep -rn "#[0-9A-Fa-f]\{6\}" src/web/templates`)
- [ ] 문구가 6장 규칙(동사 통일, 오류 원인+해결, 빈 상태 다음 행동)을 따른다
