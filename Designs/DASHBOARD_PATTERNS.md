# DASHBOARD_PATTERNS — 앱 화면 구조 패턴 카탈로그 (A~O)

작성일 2026-10-14. 13개 제품의 앱 화면(대시보드, 관리자, 운영 콘솔)을 기획하거나 구현할 때 이 문서를 따른다. 실제 운영 중인 제품에서 검증된 화면 구조 15개를 코드(A~O)로 정의해, 화면마다 레이아웃을 새로 고민하지 않고 "이 화면은 B + G시트"처럼 지정하게 한다. 토큰·컴포넌트 규칙은 `DESIGN_SYSTEM.md`, 대시보드와 랜딩의 구분은 `DESIGN_PRINCIPLES.md`, 제품별 시각 레퍼런스는 `REFERENCES.md`에 있다. 이 문서는 **화면의 뼈대**만 정한다. 공개 랜딩(메인페이지)은 대상이 아니다. 화면의 **시각**(색·밀도·분위기, V-A~V-N)은 `DASHBOARD_VISUAL.md`가 정하며, 앱 화면을 디자인할 때는 이 문서의 구조와 그 문서 1장의 필수 분석 절차를 함께 거친다.

## 1. 쓰는 법

| 항목 | 규칙 |
|---|---|
| 2층 구조 | 패턴의 정의는 이 문서 한 곳(공용)에 둔다. 어떤 화면이 어떤 패턴인지는 각 제품 `03_SCREENS_UX.md` 화면 표의 `패턴` 열에 적는다(제품별) |
| 시각 지정 | 구조 코드 옆에 `DASHBOARD_VISUAL.md`의 시각 아키타입을 `· 시각 V-C(#9)` 형식으로 함께 적는다(두 겹 표기). 근거가 없으면 `시각 없음` |
| 표기법 | 패턴 코드를 `+`로 잇는다. A(앱 셸)는 모든 앱 화면의 기본이라 생략해도 된다. 변형은 코드 뒤에 붙인다: `B + G시트`(목록에서 상세를 옆 시트로), `B → G페이지`(목록에서 상세 페이지로 이동), `C → B`(지표를 누르면 목록으로 드릴다운) |
| 작업 지시 | 화면 단위 작업은 `DESIGN_SYSTEM.md` 10장 템플릿을 쓰고 `패턴:` 줄에 코드를 적는다. 코드만 적고 끝내지 않는다. 이 문서 3~4장의 필수 요소 중 이 화면에서 뺄 것이 있으면 적는다 |
| 견적·공수 | 화면 수를 패턴별로 센다(예: B 12개, D 3개, H 1개). 같은 패턴은 두 번째부터 공수가 크게 준다 |
| 맞지 않는 화면 | 15개 중 어디에도 맞지 않으면 억지로 끼우지 않는다. `패턴` 열에 `고유`라고 쓰고 화면 설명을 따로 적는다. 같은 `고유` 화면이 두 제품에서 나오면 이 문서에 새 코드로 올린다(8장) |
| 문서는 지금, 코드는 나중에 | 이 카탈로그와 `패턴` 열은 기획 단계에서 채운다. 패턴 컴포넌트 구현은 8장 기준을 따른다 |

## 3. 뼈대와 기본 패턴

### A. 앱 셸

| 항목 | 내용 |
|---|---|
| 구성 | 왼쪽 사이드바(제품 내비게이션) + 상단 바(검색, 조직·워크스페이스 전환, 알림, 계정) + 페이지 슬롯. 오른쪽 AI 패널은 선택(아래) |
| 필수 요소 | 사이드바 접기(아이콘만 남김) 상태 유지, 현재 위치 표시, 페이지 제목과 주 행동 버튼 1개(페이지 헤더), 1024px 미만에서 햄버거 메뉴, 키보드 검색 열기(⌘K / Ctrl+K) |
| 가져올 것 | Vercel·Supabase Studio의 조용한 셸(중립 배경, 강조색은 현재 위치와 주 행동에만), 조직 전환을 상단 왼쪽에 두는 배치 |
| 피할 것 | 사이드바 메뉴 15개 이상 평면 나열(그룹으로 묶는다), 셸에 제품 일러스트·그라디언트, 권한 없는 메뉴를 자물쇠로 노출(숨긴다) |
| AI 패널(선택 레이어) | 셸 오른쪽에서 열리는 채팅 패널. 현재 페이지 맥락(선택한 레코드 등)을 넘긴다. 메시지 스레드·출처 칩은 `DESIGN_SYSTEM.md` 5장의 AI 채팅 레퍼런스를 따른다 |

### B. 리스트-상세

| 항목 | 내용 |
|---|---|
| 구성 | 필터 바(검색, 필터 칩, 저장된 뷰) + 고밀도 표 + 상세(옆 시트 또는 상세 페이지) |
| 필수 요소 | 컴팩트/기본 두 밀도(`DESIGN_SYSTEM.md` 6장), 정렬, 페이지네이션 또는 가상 스크롤, 다중 선택 후 일괄 작업, 필터·정렬·페이지 상태를 URL에 남김(새로고침·공유해도 같은 화면), 숫자 열 오른쪽 정렬과 tabular 숫자, 빈 상태(필터 결과 없음과 데이터 없음을 구분), 로딩 스켈레톤 |
| 상세 여는 방식 | 필드가 적고 빠른 수정이 많으면 `G시트`(오른쪽 시트, 목록 유지). 탭·이력·연관 레코드가 많으면 `G페이지`(전체 페이지). 한 제품 안에서 같은 종류의 레코드는 한 방식으로 통일한다 |
| 가져올 것 | Linear의 키보드 이동(위아래로 행 이동, Enter로 열기), Attio의 저장된 뷰와 열 선택 |
| 피할 것 | 행마다 장식 아이콘, 행 호버 전환 효과, 상세를 모달로 여는 것(목록 맥락을 잃는다) |

### C. KPI 오버뷰

| 항목 | 내용 |
|---|---|
| 구성 | 핵심 지표 1개를 크게 + 보조 지표 2~4개를 작게 + 추이 차트 1개 + 최근 이벤트 목록 |
| 필수 요소 | 모든 숫자는 누르면 해당 목록(B)으로 드릴다운(`C → B`), 기간 선택과 이전 기간 대비, 지표 정의 툴팁, 데이터 없음 상태 |
| 가져올 것 | Stripe의 위계(가장 중요한 숫자 하나가 화면을 지배), 차트와 표가 같은 필터를 공유하는 구성 |
| 피할 것 | 같은 크기 카드 4~8개 나열(`DESIGN_PRINCIPLES.md` "모든 지표를 같은 카드로 만들지 않음"), 의사결정에 쓰지 않는 지표, 게이지·도넛 남발 |
| 주의 | 템플릿마다 들어 있어 흔하지만 가장 많이 오용되는 패턴이다. 홈에 쓸지는 5장 기준으로 정한다 |

### G. 레코드 상세

| 항목 | 내용 |
|---|---|
| 구성 | 상단 요약(이름, 상태 배지, 핵심 필드 3~5개, 주 행동) + 탭(개요, 연관 레코드, 파일 등) + 오른쪽 활동 타임라인 |
| 필수 요소 | 타임라인에 시스템 이벤트(상태 변경, 결제, 발송)와 사람의 메모를 한 줄기로 시간순 표시, 인라인 편집(필드를 눌러 바로 수정), 변경 이력, 삭제 등 위험 행동은 메뉴 안쪽에 |

| 피할 것 | 탭 7개 이상, 모든 필드를 한 화면에 나열한 긴 폼 |

## 5. 홈 화면 고르기

C(KPI 오버뷰)는 홈의 기본값이 아니다. 사용자가 그 제품에 **왜 들어오는가**로 정한다.

| 제품 성격 | 사용자가 들어오는 이유 | 홈 |
|---|---|---|
| 숫자가 의사결정을 이끄는 제품(매출, 광고 성과, 주식) | 숫자를 보고 판단하려고 | C, 지표를 누르면 B 또는 L로 |
| 처리할 일이 쌓이는 제품(상담, 원고, 주문, 영상 잡) | 일을 처리하려고 | "오늘 처리할 일" 목록(B 또는 F 변형) + 상단에 숫자 1~2개만 |
| 만드는 도구(빌더, 에디터, 자동화) | 만들던 것을 이어서 하려고 | 최근 작업물 목록 또는 M + "새로 만들기" 주 행동 |

## 6. 모든 패턴 공통 체크리스트

- 상태 5종: 기본, 로딩(스켈레톤), 빈 상태(다음 행동 안내), 오류(무엇이 잘못됐고 어떻게 고치는지), 권한 없음(항목을 숨긴다. 제품 규칙이 따로 있으면 그 규칙).
- 라이트/다크 두 벌, 컴팩트/기본 두 밀도(`DESIGN_SYSTEM.md` 6장).
- 375px 폭: 페이지 전체 가로 스크롤 없음. 표·캘린더·캔버스는 자체 가로 스크롤 컨테이너 또는 대체 화면(목록형).
- 키보드: 주요 행동은 키보드로 가능, 포커스 링 토큰 사용.
- 상태는 색만으로 표시하지 않는다(배지 + 아이콘·텍스트).
- 문구는 `DESIGN_PRINCIPLES.md`의 문구 규칙(일관된 동사, 오류, 빈 상태)을 따른다.

## 8. 공용화 기준

| 단계 | 조건 | 위치 |
|---|---|---|
| 정의 | 기획 단계에서 바로 | 이 문서 + 제품 03장 `패턴` 열 |
| 제품 안 구현 | 그 제품에서 처음 쓸 때 | 제품 저장소 `apps/web/src/components/patterns/<코드>-<이름>/`(제안). 기본 컴포넌트(`components/ui/`)만 조합하고 hex를 쓰지 않는다 |
| 공용 승격 | 같은 패턴이 두 제품 이상에서 구현되고, 두 구현의 차이가 토큰과 문구뿐일 때 | 공용 키트(admin-suite의 `packages/admin-kit`처럼 제품군 공용 패키지). 승격하면 이 문서 해당 패턴 절에 위치를 적는다 |
| 새 패턴 추가 | `고유` 화면이 두 제품에서 같은 구조로 나올 때 | 이 문서 2장에 다음 코드(P, Q…)로 추가 |

- 쓰이지 않은 패턴을 미리 구현하지 않는다(유지보수 비용만 생긴다).
- A(앱 셸), B, H는 거의 모든 제품이 쓰므로 첫 제품 구현 때부터 공용 승격을 염두에 두고 만든다.
