## 1. 필수 분석 절차 (대시보드 화면을 디자인할 때마다)

화면 하나를 디자인·구현하기 전에 아래 7단계를 순서대로 거치고, 결과를 제품 `03_SCREENS_UX.md` 화면 표(또는 `DESIGN_SYSTEM.md` 10장 작업 지시)에 적는다. 단계를 건너뛰면 작업을 시작하지 않는다.

| 단계 | 질문 | 판단 근거 | 기록할 곳 |
|---|---|---|---|
| 1. 사용자가 왜 들어오나 | 숫자를 보고 판단 / 일을 처리 / 만들던 것을 이어서? | `DASHBOARD_PATTERNS.md` 5장 | 홈 화면 결정 |
| 2. 구조 | 이 화면의 뼈대는 A~O 중 무엇인가 | `DASHBOARD_PATTERNS.md` 2~4장 | `패턴` 열 |
| 3. 트레이딩 문법 적합도 | 숫자가 실시간으로 바뀌고, 그 숫자를 보고 바로 행동하는가 | 5장 | 적합 / 일부 화면 / 부적합 |
| 4. 선택 기준 3가지 | 행동 빈도, 레코드 수, 사용자 숙련도 | 4장 | 시각 아키타입 후보 |
| 5. 시각 아키타입 | V-A~V-N 중 무엇을, 어느 영역에만 쓰나 | 3장, 8장 | `시각` 열 (`V-C(#9)` 형식) |
| 6. 가져오지 않을 것 | 아키타입의 요소 중 이 제품에서 빼는 것 | 3장 "주의", 6장, 9장 | 작업 지시 `빼거나 바꿀 것` |
| 7. 색·숫자 규칙 확인 | 포인트컬러 1개, 상승·하락 의미 토큰, 브랜드색 분리, tabular 숫자 | 6장 | 검증 항목 |

## 2. 두 겹 표기

구조(레포 A~O)와 시각(V-A~V-N)은 코드가 겹치지 않도록 시각 쪽에 `V-`를 붙인다.

```
<구조> · 시각 <V-코드>(<카탈로그 번호>)[, <영역>에만 <V-코드>]

예) stock-dashboard 홈:  C → B · 시각 V-C(#9), 종목 상세에만 V-A
예) nomad-commerce 상품: B + O · 시각 V-D(#26, #43)
```

- 구조가 정답이고 시각은 참고다. 시각 아키타입은 색·밀도·분위기만 정하고 정보 배치·빈 상태·권한·오류는 `DASHBOARD_PATTERNS.md`를 따른다.
- 시각을 지정할 근거가 없으면 `시각 없음`이라고 적는다. 빈칸으로 두지 않는다.

## 5. 트레이딩 문법 적합도

판단 기준은 "숫자가 실시간으로 바뀌고, 그 숫자를 보고 바로 행동하는가"다. 맞지 않는 제품에 트레이딩 느낌을 입히면 정보는 늘지 않고 화면만 시끄러워진다.

| 적합도 | 제품 | 적용 범위 |
|---|---|---|
| 적합 | stock-dashboard, live-poll, nomad-commerce, nomad-video | 주요 화면에 V-A·V-B·V-C·V-D 적용 가능 |
| 일부 화면 | admin-suite(ERP 매출), nomad-blog(제휴 수익), flora-publishing(인세·정산 탭), book-trailer(구매 링크 클릭), local-news(광고·기사 성과), astro-ai(운영자 화면) | 괄호 안 화면에만. 나머지 화면은 그 제품의 기본 시각 |
| 부적합 | nomad-docs, toon-factory, microweb-studio, study-note, website-floria, arch-studio | 트레이딩 요소(캔들, 호가창, 네온 다크)를 쓰지 않는다 |

새 제품이 생기면 이 표에 먼저 넣고 시작한다.

## 6. 레이아웃·색·숫자 규칙

### 6.1 레이아웃

| 규칙 | 내용 |
|---|---|
| 정보 위계 | 위에서 아래로 **KPI(숫자) → 추이(차트) → 근거(테이블)**. 분석한 76개 대부분이 이 순서다 |
| 기본 골격 | 왼쪽 아이콘 사이드바(구조 A) + 상단 KPI + 메인 차트 + 보조 위젯 + 하단 테이블. 단 KPI는 `DASHBOARD_PATTERNS.md` C의 규칙대로 핵심 1개를 크게, 같은 크기 카드 나열 금지 |
| 위젯 수 | 한 화면 8개 이하. 넘으면 역할별 탭 |
| 차트 3종 표준 | 에어리어(추이), 막대(비교), 도넛·링(비중·목표). **캔들은 실시간 가격이 있는 화면에만**(stock-dashboard 종목 상세 등) |
| 라이트/다크 기본값 | 화면 성격별로 기본값을 정한다: 업무·정산·입력은 라이트, 실시간·모니터링은 다크. 두 벌 모두 만드는 것은 `DESIGN_SYSTEM.md` 6장대로 |

### 6.2 색

| 규칙 | 내용 |
|---|---|
| 포인트컬러 | **화면당 1개.** CTA·선택 상태·진행바·현재 위치에만 쓴다 |
| 글로우·그라데이션 | 화면에 한 곳만(배경 또는 결과 카드). 앱 셸·사이드바·표에는 금지 |
| 브랜드색과 상승·하락색 분리 | 브랜드색은 상승·하락 어느 쪽과도 겹치지 않는 색. 분석에서 그린을 상승과 브랜드에 겸용한 경우가 가장 많았지만 의미가 섞이므로 따르지 않는다 |
| 상승·하락 의미 토큰 | 컴포넌트는 `--color-up`, `--color-down`만 참조한다. hex를 직접 쓰지 않는다 |
| 국내 주식 관례 | **stock-dashboard 시세는 상승 빨강 / 하락 파랑**(국내 관례, 기획서 3.1절). 첫 PDF 8장의 "상승 초록 / 하락 빨강"은 해외 관례라 정정됐다. 값은 stock-dashboard D-5 결정 후 `tokens.css`에서만 바꾼다 |
| 다른 제품의 증감 | 매출·성과처럼 "증가 = 좋음"인 지표는 성공색(초록)을 써도 된다. 국내 시세 관례는 주식 시세에만 적용 |
| 색만으로 전달 금지 | 부호(+/−)·화살표·텍스트를 함께 표시한다 |
| 제품 간 구분 | 같은 다크 베이스·같은 포인트컬러를 두 제품이 공유하지 않는다(`REFERENCES.md`). 크립토 네온(블랙 + 마젠타·네온 그린, #13·#59류)은 쓰지 않는다 |

### 6.3 숫자

- 모든 숫자에 tabular(등폭) 숫자. 실시간 갱신 때 글자가 흔들리지 않게 한다.
- 숫자 열은 오른쪽 정렬, 단위·부호 일관.
- 실시간 값이 바뀔 때 깜빡임 강조는 짧게(색 배경 1회), 계속 깜빡이는 효과 금지.

## 10. 작업 지시와 검증

`DESIGN_SYSTEM.md` 10장 화면 템플릿에 `시각:` 줄을 함께 적는다.

```
패턴: C → B
시각: V-C(#9), 종목 상세에만 V-A / 적합도: 적합 / 기본 테마: 다크
빼거나 바꿀 것: V-C의 오른쪽 거래 패널(모의주문은 Phase 3), 상승·하락 색 값(D-5 결정 대기)
```

검증 체크리스트 (스크린샷으로 확인):

- [ ] 1장 7단계 결과가 03장 화면 표 또는 작업 지시에 적혀 있다
- [ ] 위계가 KPI → 추이 → 근거 순서다
- [ ] 포인트컬러가 화면에 1개이고, 브랜드색이 상승·하락색과 겹치지 않는다
- [ ] 상승·하락이 의미 토큰(`--color-up`/`--color-down`)과 부호·텍스트로 표시된다
- [ ] 글로우·그라디언트가 셸·표에 없다
- [ ] 숫자가 tabular, 오른쪽 정렬이다
- [ ] 목업·퍼스펙티브·실사 배경 같은 썸네일 연출이 제품 화면에 없다
- [ ] 다른 제품과 다크 베이스·포인트컬러가 겹치지 않는다
